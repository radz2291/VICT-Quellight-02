# Phase 2 hosted memory operations

The selected services remain Vercel Hobby and the existing free Supabase project. Every model-backed role uses the existing `zai-coding-plan/glm-5.3-flash` profile. Its `ZHIPU_API_KEY` remains a server Secret in Vercel; the scheduler does not receive it.

Original Phase 1 transcripts and `quellight_memory_v1` remain intact. The C12 recoverable profile uses private schema `quellight_memory_v2`. First admission of a new native chat imports that conversation's original public sources once, preserving stable IDs and timestamps. Opening the inspector performs reads only and does not initiate that import. Runtime uses the restricted `ql_app_runtime` role; migration login and database CREATE are disabled outside controlled operator provisioning.

The four product migrations add versioned settings, durable learning jobs/import markers, durable care commands, and private delivery configuration. All new tables use RLS. Browser roles receive no grants. Delivery configuration and delivery records deliberately have no runtime policy: only the database operator/scheduler can use them. Learned content and source authority remain behind VICT's public native-memory boundary.

Supabase `pg_cron` checks once per minute for due work. If none exists, it makes no HTTP request. `pg_net` sends the fixed empty JSON request to `/api/internal/memory/wake`, authenticated with the separate `QUELLIGHT_MEMORY_DISPATCH_SECRET`. Vault stores the same value as `quellight_memory_dispatch`; protected Preview testing additionally uses `quellight_memory_preview_bypass`. The response is HTTP 202 acknowledgement, not a completion claim. Its ten-second transport timeout covers that acknowledgement only, not model reasoning.

The route continues the dispatcher with Vercel's background-work facility. Turn settlement commits the public transcript and learning intent together. A response can also initiate delivery immediately; it does not depend on the browser staying open. Claims are durable and only one maintenance job per account is admitted at a time, while different accounts remain eligible. Native resource/thread fences retain execution authority. Pending care is reconciled before ordinary learning.

Vercel's actual Hobby function ceiling is 300 seconds for turn admission, memory care and worker wake. No application model timeout, output-token cap, reasoning budget or generation-step cap was added. A lost process leaves truthful pending/uncertain state. Later delivery uses the same native operation identity and reconciles prepared or completed work before deciding whether any new inference is needed. Delivery retries back off without a fixed retry count.

The operator controls `memory_delivery_configuration.enabled` and its exact origin. Use the qualified protected Preview during tests; switch to `https://quellight.com` only after its Production deployment is READY. The private scheduler cannot be configured or invoked by a browser/application role. Do not log Vault values, authorization headers, session cookies, database URLs or provider credentials.

Qualification and release records are in `../../qualification/phase2-hosted`; current deployment status is in `../STATE.md`. Exact source, archive and lock identities accompany the records. The source-based [ARA comparison](PHASE-2-ARA-COMPARISON.md) is distinct from a controlled comparison between live models.

The post-migration security check found intentional deny-all RLS notices for the two operator-only delivery tables and the retained inactive v1 OM table. These tables are not missing an application policy. [Supabase RLS notice reference](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy). The pre-existing leaked-password-protection notice is unchanged; no paid feature was enabled. [Supabase password protection reference](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
